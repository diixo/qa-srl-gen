# Журнал разбора исходного корпуса

Эта папка содержит подробный результат автоматического разбора всех **736 040**
записей из `data/eng-base.jsonl`. Журнал связывает каждое исходное предложение
с его токенами, вариантами анализа и исполняемым шаблоном.

## Формат файлов

Файлы `00000.jsonl.gz` — `00073.jsonl.gz` представляют собой JSONL, сжатый gzip:
одна JSON-запись на строку. Всего **74 файла**, около **214 МБ** в сжатом виде.
Каждый файл содержит 10 000 записей, последний — 6 040. Порядок файлов и строк
соответствует порядку записей в исходном корпусе.

Эти числа описывают исходный eng-base. Новые результаты майнинга дописываются
в те же файлы отдельными gzip-блоками. Общий `manifest.json` хранит диапазоны
каждого источника; нумерация строк остаётся локальной для него. Читать журнал
целиком следует через `TemplateBank.occurrences()`, чтобы не включать
незавершённые хвосты после прерванного добавления.

| Поле записи | Содержимое |
| --- | --- |
| `line`, `idx` | Номер строки и идентификатор исходной записи |
| `text` | Исходный текст без изменения |
| `template_id`, `bindings` | Идентификатор шаблона и исходные заполнения его слотов |
| `tokens` | Все токены: текст, позиции символов, леммы, части речи, морфология, синтаксические связи и словарные варианты чтения |
| `attributes` | Прилагательные, их степени сравнения, модификаторы и связь со слотом описываемого слова, если она установлена |
| `predicate_groups` | Предикаты и конструкции с частицами, предлогами и наречиями |
| `analysis_status` | Тип анализа записи, включая явно отмеченные альтернативы для пропущенных парсером команд |
| `sentence_template`, `predicate_templates` | Первоначальные синтаксические шаблоны предложения и предикатов |

Разбор имеет статус **UNREVIEWED**. Словарное чтение токена как прилагательного
или глагола не означает, что именно это чтение верно в данном контексте.
Основное решение парсера и альтернативы сохранены отдельно.

## Нужна ли папка для работы

| Операция | Нужен `occurrences/` |
| --- | --- |
| Генерация по готовому банку через CLI или UI | Нет: используются `templates/` и отдельные словари банка |
| Полная проверка банка командой `template_validation` | Да |
| Поиск исходных употреблений и разбор ошибок автоматической разметки | Да |
| Анализ всех сохранённых токенов и альтернатив без повторного запуска NLP-модели | Да |

Удаление папки **не останавливает генерацию**, но удаляет подробный журнал и
делает повторную полную проверку банка невозможной. Существующий
[`validation.json`](../validation.json) отражает уже выполненную проверку и
не заменяет сами записи. Если нужно освободить место, можно сохранить папку
отдельной копией и вернуть её перед проверкой.

Из одних файлов `templates/` полностью восстановить журнал нельзя: там нет
всей привязки к исходным строкам и полного анализа каждого токена.
Восстановление выполняется повторной компиляцией `eng-base.jsonl` в **новый**
каталог с соответствующей моделью и словарными ресурсами. Версии и SHA-256
зафиксированы в [`manifest.json`](../manifest.json), команда восстановления —
в [README банка](../README.md).

## Как прочитать файл

Распаковывать весь журнал на диск не требуется. Пример для запуска Python
из корня проекта:

```python
import json
from semantic_corpus.template_bank import TemplateBank

bank = TemplateBank()
first_record = next(bank.occurrences())
print(json.dumps(first_record, ensure_ascii=False, indent=2))
```

Компилятор и проверка выбирают только `*.jsonl.gz`, поэтому этот README
не участвует в подсчёте или обработке записей.
