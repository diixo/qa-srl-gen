# Генерация корпусов и обучающих датасетов

Через **New job** (`/pipeline`) можно создавать синтетические корпуса, импортировать тексты, получать разметку, генерировать вопросы и экспортировать данные для обучения. Для диалоговых задач **History, Memory и Extraction** предусмотрена отдельная страница **Chat dataset** (`/chat-dataset`). Ниже описаны возможности текущего кода интерфейса.

Оба пути подготавливают данные. Обучение модели запускается отдельно: имеющийся GPT-2 SFT trainer работает через CLI и поддерживает форматы Chat dataset.

**Операции в New job**

Названия в первом столбце совпадают с пунктами поля **Operation**. Пути файлов указаны относительно каталога задания: `artifacts/ui/jobs/<id>/`.

| Операция | Что получаем | Основные артефакты | Для какого обучения подходит / что требуется дальше |
| --- | --- | --- | --- |
| **Synthetic corpus** | Английские ситуации из курируемых фреймов и доступных mined-шаблонов общего Built-in pool; разметка и QA в пределах поддерживаемых конструкций | `store/`, `sft.jsonl`, `bio.jsonl`, `generation-summary.json`, `report.json` | SFT на вопросах о действиях, участниках, свойствах, типах сущностей, отрицаниях и других поддерживаемых аспектах; токенная классификация по разметке. Автоматические mined-QA могут оставаться `UNREVIEWED` — см. пояснение ниже. |
| **DailyDialog: full pipeline** | Импорт выбранного файла диалогов, локальная разметка речевых актов правилами, QA и экспорт | `result/store/`, `result/sft.jsonl`, `result/bio.jsonl`, `result/report.json`, `result/summary.json` | QA о функции реплики: вопрос, просьба, согласие, отрицание и т. п. Правила не создают семантическую разметку сущностей и предикатов; BIO при такой разметке содержит `O` и не является полезным набором положительных NER-примеров. Этот обработчик назначает всем документам `train`. |
| **Text / dialogue import** | Корпус из TXT / JSONL с текстом либо JSONL с репликами диалогов; сохранение контекста и удаление дублей | `store/`, `report.json` | Промежуточный материал. Обучающие SFT/BIO-файлы на этом шаге не создаются; следующий шаг — **Corpus annotation**. |
| **QA-SRL Bank import** | Тексты, предикаты, аргументы и исходные вопросы/ответы из QA-SRL Bank | `store/`, `sft.jsonl`, `bio.jsonl`, `report.json` | SFT на извлечении ответов об участниках и обстоятельствах действия. BIO отражает только имеющиеся типизированные текстовые фрагменты; связи ролей сохраняются в корпусе. |
| **Corpus annotation** | Новый проход разметки и генерация QA в независимой копии выбранного корпуса | `store/`, `sft.jsonl`, `bio.jsonl`, `report.json` | **Rules (offline)** размечает диалоговый слой. **HTTP teacher** позволяет получать разметку через настроенный сервис; содержание и качество зависят от его ответа. QA переаннотированных документов пересоздаются. |
| **QA generation** | Новые вопросы по последним аннотациям документов, с выбранными ограничениями количества и доли вопросов без ответа | `store/`, `sft.jsonl`, `bio.jsonl`, `report.json` | Расширение или балансировка QA-набора для SFT. Отсутствующую семантическую разметку этот режим не создаёт. |
| **SFT / BIO export** | Экспорт существующих QA и последних аннотаций выбранного корпуса | `sft.jsonl`, `bio.jsonl`, `report.json` | Подготовка файлов для SFT и токенной классификации. Новые тексты, вопросы и аннотации не генерируются. |
| **Corpus report and validation** | Проверки целостности, распределений и утечек между выборками | `report.json` | Контроль корпуса; обучающих примеров не добавляет. |
| **QA-SRL Bank validation** | Проверка структуры выбранного файла Bank | Результат в журнале задания | Диагностика источника перед импортом. |
| **Question round-trip** | Проверка разбора и обратного восстановления вопросов QA-SRL | Результат в журнале задания | Диагностика формата вопросов. |
| **Candidate extraction** | Предварительные кандидаты разметки для введённого текста | Результат в журнале задания | Проверка работы анализатора; это не готовая подтверждённая разметка для обучения. |
| **Verb forms** | Поиск форм введённых глаголов | Результат в журнале задания | Проверка лексических ресурсов; обучающий датасет не создаётся. |
| **Entity pool proposals** | Предложения по пополнению пула сущностей с примерами употребления | `proposals.json` | Кандидаты для проверки и последующего пополнения общего пула. Автоматического допуска к генерации этот шаг не означает. |

Каждое задание также сохраняет `config.json` и журнал выполнения. Историю, состояние и скачивание результатов можно открыть через **Job history**. Если задан `CORPUS_UI_ROOT`, корень результатов меняется: `<CORPUS_UI_ROOT>/jobs/<id>/`.

**Что находится внутри обучающих файлов New job**

| Артефакт | Формат записи | Целевой навык модели | Существенные особенности |
| --- | --- | --- | --- |
| `sft.jsonl` | Одна JSON-запись на строку: `prompt`, `completion`, `text`, `kind`, `answerable`, идентификаторы и `metadata` | Отвечать на вопрос по текстовому контексту; извлекать нужный ответ; распознавать отсутствие ответа | `prompt` содержит контекст и вопрос, `completion` — целевой ответ. Loss следует считать по ответу. `text` — их объединение для просмотра. Это не формат `messages` диалогового trainer. |
| `bio.jsonl` | `document_id`, `tokens`, `tags`, `split` | Выделять типизированные фрагменты текста: сущности, действия/состояния, свойства — в пределах доступной разметки | Поле **Export tagging scheme** выбирает BIO или BILOU; имя файла остаётся `bio.jsonl`. Проекция теряет вложенность, дополнительные метки и связи. Это не полный граф семантических ролей. |
| `store/` | JSONL-таблицы: `documents`, `passages`, `utterances`, `annotation_runs`, `spans`, `relations`, `dialogue`, `qa_examples`, `dataset_versions` | Основа для подготовки других обучающих представлений | Сохраняет исходные тексты, разметку, связи, QA и происхождение данных. Для trainer нужен подходящий экспорт; сами таблицы не являются одним готовым обучающим файлом. |

В QA поддерживаются отдельные и составные вопросы, вопросы с контекстом, о типах сущностей и онтологии, свойствах, речевых актах, вопросы «да/нет», перефразировки и случаи без ответа. Набор реально созданных типов зависит от аннотаций: каждый документ не обязан давать все виды QA.

**Качество и объём Synthetic corpus.** Поле **Situations per frame** задаёт количество ситуаций на каждый курируемый фрейм; одна ситуация может дать несколько QA. **Examples per mined template** задаёт квоту до фильтрации по split и удаления дублей; `0` отключает mined-часть. **Recombine observed slot fillers** включает новые сочетания заполнений, которым требуется грамматическая и смысловая проверка с учётом ограничений шаблонов.

Для поддерживаемых mined-конструкций код может создать извлекаемые QA и записать их в `sft.jsonl` с `metadata.review_status = UNREVIEWED`. Перед использованием такого материала в проверенном обучающем наборе нужен допуск или отбор по происхождению и статусу. Документы с неполной семантикой остаются в корпусе; автоматическая разметка `template_semantics` пропускается при BIO-экспорте. Успешное создание файлов и чистый отчёт о целостности сами по себе не подтверждают смысл каждого примера.

**Разделение выборок New job.** В синтетической генерации и импорте Bank выбирается `train`, `dev` или `test`. Импорт обычного текста распределяет документы детерминированно, импорт диалогов использует выбранный split. Общий экспорт пишет единые `sft.jsonl` и `bio.jsonl`, а не три отдельных файла: если в исходном корпусе несколько выборок, их нужно разделять по принадлежности документов. У SFT-записи нет отдельного верхнеуровневого поля `split`; надёжная привязка — `document_id` к `store/documents.jsonl`.

**Диалоговые датасеты: отдельная страница Chat dataset**

Один запуск создаёт все три представления в `artifacts/ui/jobs/<id>/dataset/` и архив `chat-dataset.zip`. Для каждого представления формируются **JSON-массивы** `train.json`, `validation.json`, `test.json`.

| Представление | Файлы внутри `dataset/` | Что подаётся модели | Что модель учится выдавать |
| --- | --- | --- | --- |
| **History** | `history/train.json`, `history/validation.json`, `history/test.json` | История разговора и последняя реплика пользователя | Краткий ответ с опорой на историю, включая уточнение неоднозначности или признание отсутствия сведений. |
| **Memory** | `memory/train.json`, `memory/validation.json`, `memory/test.json` | Текстовое представление текущей памяти, последняя реплика ассистента и новое сообщение пользователя | Ответ на основе памяти. При генерации память задаётся симулятором; этот набор сам по себе не обучает извлекать её из разговора. |
| **Extraction** | `extraction/train.json`, `extraction/validation.json`, `extraction/test.json` | Текущая память, новая реплика пользователя и контекст последней реплики ассистента | Команды изменения памяти: `SET`, `REMOVE`, `NO_CHANGE`, а в соответствующих сценариях — `EVENT`, `PARTIAL`, `MINED`, `QUOTE` и их варианты. Учитываются отрицание, модальность, время, исправления и доступный смысл неполных реплик. |

Запись содержит `messages` с ролями `system`, `user`, `assistant`; целевой ответ расположен в сообщении `assistant`. Поле **Include metadata** управляет сохранением внешних идентификаторов, типа задачи и других служебных полей. History и Memory дают парные ответы для одного сценария; Extraction содержит примеры отдельных обновлений, поэтому его размер может отличаться.

Сейчас доступны **18 семейств сценариев**, либо **17** при включённом **User and assistant only**: исключается `different_people`. Они охватывают запоминание и исправление фактов, различение людей, отрицание, желания и предложения в отличие от совершённых действий, ссылки на варианты, неоднозначность, отсутствие информации, возврат к теме, отзыв факта, возможности ассистента, область действия модальности, ход и завершение событий, исправление событий, состояния, mined-предикаты и смысл коротких/незавершённых реплик.

| Настройка Chat dataset | Значение для результата |
| --- | --- |
| **Training / Validation / Test dialogues per task** | Количество диалогов на каждое семейство сценариев в соответствующей выборке. Это не общее число диалогов. |
| **Mined training dialogues** | Отдельная квота для `mined_predicates`: `0` — охват всех mined-предикатов вариантами yes/no/unknown; положительное число — отдельная квота; пустое поле — обычная квота на задачу. Это не обработка всех исходных диалогов DailyDialog. |
| **Seed** | Воспроизводимость при одинаковых ресурсах и настройках. |
| **Maximum example tokens (GPT-2)** | Ограничение полного ChatML-примера, включая ответ; по умолчанию 768. Длинные сценарии заменяются без обрезания. Нужны зависимости токенизации и локальный GPT-2 tokenizer; пустое поле отключает проверку. |

Дополнительные файлы `manifest.json`, `*.episodes.jsonl`, `mined-coverage.json`, `mined-review.json`, а при проверке длины — `token-lengths.json` и `length-rejections.jsonl`, служат для проверки и воспроизводимости. Обучающие входы — файлы трёх представлений. В Extraction адаптация `utterance_interpretation` описывает смысл реплики; она не подтверждает истинность или завершение упомянутого действия. Цитируемый mined-текст также не становится автоматически подтверждённым событием.

**Выбор маршрута по цели**

| Цель | Маршрут в интерфейсе |
| --- | --- |
| Получить QA/SFT из общего пула | **New job → Synthetic corpus**, затем проверить `generation-summary.json`, `report.json` и статусы mined-QA. |
| Получить QA/SFT из своих текстов | **Text / dialogue import → Corpus annotation → QA generation**; аннотация уже делает первичный экспорт, отдельная QA generation нужна для его пересоздания/балансировки. |
| Обучать извлечение и обновление диалоговой памяти | **Chat dataset → `dataset/extraction/`**. |
| Обучать ответы по истории или готовой памяти | **Chat dataset → `dataset/history/` или `dataset/memory/`**. |
| Подготовить данные для токенной классификации | Размеченный корпус → **SFT / BIO export → `bio.jsonl`**. |
| Пополнить ресурсы генерации новыми шаблонами | Отдельная страница **Template mining** (`/template-mining`); ресурсы сохраняются в общем `data/mined-templates/`. Структурная проверка майнинга не заменяет смысловой допуск. |

Старый пункт **Corpus templates: verbs and adjectives** доступен для исторических заданий, но скрыт при создании нового New job. Текущая генерация из общего пула запускается через **Synthetic corpus**.
