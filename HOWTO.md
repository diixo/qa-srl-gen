

# New Job

### Synthetic corpus

Начни с Synthetic corpus — запуска на 100 ситуаций для каждого фрейма (сейчас 800 всего). Он использует встроенные фреймы и пулы сущностей и проходит весь путь до готовых обучающих примеров.

* В New Job установи:

|        Поле       |      Значение    |
| ----------------- | ---------------- |
| Operation         | Synthetic corpus |
| Situations per frame | 100           |
| Seed              | 42               |
| Split             | train            |
| Entity pool       | Built-in pool    |
| Export tagging scheme | BIO          |
| Maximum QA per kind per document | Оставь пустым |
| Maximum unanswerable share | Оставь пустым |

Нажми **Queue job**. Откроется страница задания, воркер запустится автоматически.
Этот запуск выполнит генерацию текстов, сохранение разметки, создание QA, экспорт и проверку качества. 

После статуса Completed можно:
* открыть Browse corpus records и посмотреть корпус;
* скачать `sft.jsonl` — обучающие QA-примеры;
* скачать `bio.jsonl` — токенную разметку;
* посмотреть `report.json` — отчёт качества.

100 — это число разных текстов ситуаций **для каждого фрейма**, а не число QA-пар.
При восьми фреймах получится `100 × 8 = 800` ситуаций; QA-примеров будет больше,
их число зависит от разметки и настроек балансировки. Общий объём отображается
под формой и используется в прогрессе задания.

Каждый фрейм получает отдельную последовательность от `Seed` и имени глагола.
Добавление или перестановка фреймов сохраняет тексты, идентификаторы и QA
остальных при неизменных определениях фреймов, пуле и настройках. Увеличение
`Situations per frame` продолжает последовательность каждого фрейма.

Повторяющиеся тексты внутри фрейма пересэмплируются. Если за ограниченное число
попыток нужный объём не набран, задание завершится ошибкой с именем фрейма и
полученным количеством. Уменьши значение или расширь пул выбранного `Split`.
Неудавшееся задание может оставить частичные данные; готовой версией корпуса они не считаются.

В CLI параметр `--count` у `generate`, `questions` и `build` также означает
количество ситуаций **на фрейм**. Для Python API новый режим —
`Generator.generate_per_frame(count)`; прежний `generate(count)` сохраняет
общий лимит и случайный выбор фреймов. Старые UI-задания и их повторные запуски
сохраняют прежний общий лимит. Для нового режима создай задание через **New Job**.

* Датасет создаётся на основе трёх компонентов:

| Основа            | Что используется сейчас                                     |
| ----------------- | ----------------------------------------------------------- |
| Семантические фреймы | 8 типов ситуаций: `give`, `visit`, `own`, `feel`, `move`, `see`, `say`, `buy` |
| Пулы сущностей    | Люди, животные, организации, места, предметы, эмоции, время и другие типизированные значения |
| Правила построения предложений | Допустимые роли, порядок аргументов, активный и пассивный залог, необязательные участники |


Фреймы заданы в [frames.py](/semantic_corpus/semantic_generator/frames.py), встроенный пул — в [entities.json](/semantic_corpus/semantic_generator/entities.json). Сейчас в полном пуле 183 записи сущностей, соответствующие 168 уникальным текстовым формам. Для выбранного `Split` используется только его часть пула.

Например, фрейм `give` определяет ситуацию:
```text
Кто-то передаёт что-то кому-то, возможно, где-то и когда-то.
```

Генератор подбирает допустимые значения для этих ролей и строит предложение. Из известной структуры получает разметку, вопросы и ответы. Операция **Synthetic corpus** работает по этим правилам; обращения к LLM или чтения DailyDialog в ней нет.

**Есть ещё ограничение текущего запуска**: он выбирает прошедшее или настоящее время и один допустимый шаблон предложения. В библиотеке предусмотрены отрицание, модальность, perfect и progressive, но массовый запуск через UI сейчас их не перебирает.

Для «всех вариантов» нужно определить охват:
- **Все комбинации внутри текущих ресурсов** — перебрать допустимые заполнения слотов и грамматические варианты. Такого режима пока нет.
- **Больше типов жизненных ситуаций** — расширять набор фреймов. Увеличение числа примеров или размера пула само по себе не добавит ситуации вроде обещания или сравнения.


Для твоей цели я бы следующим шагом добавил режим **контролируемого покрытия**: выбор фреймов и грамматических вариантов, заданное количество примеров на каждую комбинацию и отчёт о том, какие случаи покрыты. Это позволит понимать состав датасета, прежде чем запускать большой объём.


#### Итого:

**Synthetic corpus** — это полный цикл создания синтетического датасета, включающий финальный экспорт.

Одно задание выполняет:
```text
Фреймы + пулы сущностей → ситуации → тексты с разметкой → QA-примеры → SFT/BIO → проверка качества.
```

На выходе получаются файлы датасета, пригодные для использования в обучении.


Поэтому:
- **Synthetic corpus** — создание датасета из заданных правил и ресурсов.
- **Export** — отдельная финальная стадия подготовки обучающих файлов из уже существующего корпуса.
«Финальным датасетом» результат Synthetic corpus можно считать, когда тебя устраивают его покрытие, объём и качество. Один запуск с Split = train создаёт только обучающую часть; dev и test формируются отдельными запусками.


### Расширение функционала

Сейчас новые ситуации добавляем только кодом:

- В `frames.py` описываем новый `SemanticFrame`: роли, допустимые типы сущностей и шаблоны предложений; включаем его в `DEFAULT_FRAMES`.
- Для нового глагола добавляем его формы в `DEFAULT_PARADIGMS` в `generator.py`.

Через UI сейчас можно загружать пулы сущностей, но редактора фреймов ещё нет.
Чтобы добавлять ситуации без изменения Python, нужно вынести определения фреймов в JSON и подключить их загрузку и редактирование через UI.


Для синтетической генерации нужны определённые фреймы. Но это не ограничение обучения в целом.


Фрейм `buy` уже добавлен: он создаёт ситуации покупки физического предмета человеком или организацией, с необязательными местом и временем. Примеры: `Anna bought a red ball.`, `A red ball was bought by Anna.`, `A red ball was bought.` Продавец и цена в этом фрейме пока не моделируются.
Для нового типа ситуации, фрейм которого ещё не определён, **Synthetic corpus** не сможет целенаправленно создавать примеры.


Однако обучающие примеры о покупках можно получить другими путями:
- импортировать уже размеченные примеры из QA-SRL Bank;
- взять реальные тексты и разметить их через HTTP teacher в рамках поддерживаемой схемы;
- подготовить разметку вручную и написать адаптер импорта.

Текущий **Rules (offline)** размечает преимущественно диалоговые акты и полноценную разметку произвольных событий не заменяет.

Сам фрейм — это инструкция нашему генератору, а не жёсткое ограничение будущей модели. Модель обучается на полученных примерах и может обобщать их на новые ситуации, но такое обобщение нужно проверять.


### Расширение базы знаний
Расширение базы знаний включает добавление новых фреймов, ролей, шаблонов предложений и пулов сущностей. Это позволяет генератору создавать более разнообразные ситуации и, соответственно, получать более богатые обучающие примеры.

На примере уже добавленного глагола `buy`: описание находится и в `frames.py`, и в `semantic_generator/generator.py`.

В текущей реализации — в оба места, поскольку они отвечают за разные вещи:
- `frames.py` — определяем фрейм `BUY`: участников покупки, допустимые типы сущностей и шаблоны предложений. Затем добавляем `BUY` в `DEFAULT_FRAMES`.
- `generator.py` — добавляем формы глагола в `DEFAULT_PARADIGMS`

```python
"buy": InflectedForms("buy", "buys", "buying", "bought", "bought"),
```

Первое описывает структуру ситуации, второе — как изменяется глагол.

Если добавить только фрейм, генератор выдаст ошибку отсутствующей парадигмы. Если добавить только словоформы, ситуации покупки генерироваться не начнут.
